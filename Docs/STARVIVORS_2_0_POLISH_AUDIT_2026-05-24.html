Starvivors 2.0 Full-System Polish Audit

Prepared: 2026-05-24

Repo basis: local Starvivors workspace, current clean working tree, build passing with npm.cmd run build.

Sources reviewed: 2.0 GDD/build plan, phase notes, GameScene owned runtime fields, data registries, UI modules, system modules, asset folders, Forge registry, and source TODO/deferred markers.

Summary: The game is broad enough that polish should now be tracked as a whole-product pass, not only as isolated phase work. The strongest implemented pillars are the 2.0 run loop, mission/free-range selection, ship/loadout basics, Pulse Cannon, sector generation, squads, mothership/rare event prototypes, reward persistence, HUD/radar/results work, and the initial Asset Forge pipeline.

Main risk: Many systems are playable but not yet cohesive: menus use the new cockpit treatment unevenly, art direction is split between Forge/vector/procedural/PNG, audio is absent, accessibility/settings are placeholder-heavy, and several active objects still rely on scene-owned Phaser lifecycle code rather than focused ownership.

Status Scale

StatusMeaning
ImplementedWorks in the current build and has at least one real user path. Still may need polish.
MVPPlayable or usable but rough, incomplete in presentation, balance, content depth, or edge cases.
PrototypeFramework exists and proves direction, but needs content, final presentation, tuning, and stronger verification.
WIPActive work has begun but the product surface is not settled.
Missing/MentionedMentioned in docs, data, or plans but absent, placeholder-only, or not promoted to live gameplay.
RiskWorks now but has maintenance, readability, scaling, UX, or performance risk.
